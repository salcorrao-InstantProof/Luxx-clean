# LUXX Integrated Hosted v1.3 — Architecture

## Parent
The behavioral parent is LUXX Simplified Revenue Pilot v1.2.1. The hosted v1.3 preserves TODAY / LIBRARY / RESULTS and the baseline, tracking, attribution, authorization, frozen-prescription, measurement, revenue and candidate-specific learning contracts.

## Persistent media
Original photos/videos are immutable chunked masters. Each master receives a SHA-256. Editing creates a derivative record and derivative bytes; it never overwrites the master.

## Image preparation
- AUTO BEST is a conservative technical image adjustment, not an attractiveness score.
- Manual edits can be based on the master or another derivative.
- Provenance is preserved through parent variant IDs and edit recipes.

## Video preparation
- FFprobe records technical metadata.
- FFmpeg technical analysis uses observable scene/activity plus black/freeze/silence penalties.
- For a source around seven minutes, the current default plan targets a five-minute main cut and normally three teaser candidates.
- Actual MP4 derivatives are rendered.
- Poster frames and HLS previews are saved.
- Video EDIT can operate on the master or an existing rendered variant.
- The original remains immutable.
- Segment ranking is labelled a technical heuristic until sufficient creator-specific outcome evidence exists.

## Existing published video
A publication already on Pornhub, ManyVids, OnlyFans or another supported platform is recorded as historical truth. REVIEW EXISTING may recommend KEEP / RE-EDIT / REPLACE / RETIRE, but the historical record is not deleted or rewritten. A chosen update becomes a new prospective prescription/action.

## Decision/evidence integrity
- baseline before prospective recommendation;
- external route verification fails closed;
- SOURCE / ACTION / INTERNAL attribution ceiling is mechanical;
- ACTION routes require exact asset+variant binding for exact attribution;
- authorization/availability/platform eligibility enforced;
- prescriptions can be changed/declined while preserving lineage;
- approval revalidates and freezes the exact prescription;
- execution requires evidence/reference and creator effort;
- measurement preserves unknown vs zero and append-only corrections;
- revenue/custom events preserve attribution precision;
- candidate learning prioritizes exact variant → exact master → context fallback.

## CTA and posting guidance
CTA and timing recommendations carry an evidence basis. General psychology/operational principles are labelled as operational priors. Creator-specific directional timing is used only when sufficient comparable observations exist. No unsupported conversion-lift claim is made.

## Brand shoots
A brand/gap shoot is optional. LUXX records the documented library/funnel gap, desired assets, target platforms and brand direction. It begins as DRAFT and requires creator approval. Existing media should be reused before prescribing new production when it can satisfy the need.

## Storage
Site-wide Netlify Blob stores hold state/assets/jobs/media. Authenticated same-site endpoints mediate private media access; the app does not expose public Blob URLs as its normal media interface.


## Evidence contract (v1.7.0 RC2)

A line carries GUESS until it earns CALL. CALL requires the minimum qualifying
sample threshold **plus** favourable measured evidence. Reaching the threshold does
not by itself produce a CALL, and six observations never automatically equal CALL.

For locked PPV the buyer pays on the **pre-purchase treatment** — preview style,
delivery mode/route, audience segment, price band, attribution scope — so evidence
belongs to that treatment class and never to the hidden master. The treatment key
contains no asset id, no filename and no master identity. All of the following must
hold before a PPV line is a CALL:

- the same treatment class;
- the same attribution scope;
- a real recorded denominator (`sent_to`);
- at least the minimum qualifying sample of comparable measured results;
- **and** favourable evidence under the bounded/shrunk scorer.

Six zero-unlock sends stay GUESS. A PPV DM with no recorded `sent_to` stays GUESS,
and the denominator is never invented at recommendation time.

Cam availability is a scheduling constraint, not evidence. A configured cam time
remains GUESS / DEFAULT until creator-specific measured results support it. The
LIBRARY visual technical score describes technical usability only: it never ranks
monetization, never creates a CALL and never influences TODAY's ordering.

PRODUCE is inactive until a Library or funnel gap is documented with counted
evidence against the reviewed Library. Sufficient inventory yields NO NEW SHOOT
NEEDED, which is a valid and expected result.
