WHAT CHANGED
  For PPV sends, LUXX no longer says a PHOTO is proven. It says a pre-purchase TREATMENT is:

      PHOTO                     window_light.jpg
      PRE-PURCHASE TREATMENT    Blurred close crop -> PPV DM -> active subscribers -> $10-15
      CALL                      attached to the treatment line, never to the filename

  Because the buyer pays before seeing the file, unlock revenue cannot prove the photo.

WHEN YOU MARK POSTED
  You are now asked what you ACTUALLY sent: preview style, audience segment, price, and how
  many fans it went to. If you changed anything from what LUXX proposed, the result counts for
  what you really did. Without a real sent-to count there is no unlock rate, so the line stays
  GUESS. LUXX never invents that number.

DEPLOY
  Same Netlify site. LUXX_PASSCODE and LUXX_SESSION_SECRET must be set or the build refuses.

3. TREATMENT KEY
   preview_style | delivery_mode | audience_segment | price_band | scope
   Contains NO asset_id, master_asset_id or filename. Returns null unless preview_style AND
   audience_segment are both present, so an incomplete treatment is not a class.
   scope = route.attribution_scope | delivery_mode  (e.g. INTERNAL|PPV_DM)

4. CALL / GUESS RULE
   CALL requires ALL of:
     - same treatment class      (conversion claims only)
     - same attribution scope    (all claims)
     - a real recorded sent_to on every qualifying observation
     - n >= CALL_THRESHOLD (6, unchanged)
     - favourable evidence under the EXISTING bounded/shrunk model (ownSum > 0)
   GUESS otherwise, including: n<6, missing denominator, missing treatment fields, different
   treatment class, different scope, feed/post with no observable exposure, unfavourable
   evidence. Legacy records without treatment fields stay GUESS and are never backfilled.

5. candidateScore / EVIDENCE-KEY CHANGES  (patched in place; no second scorer exists)
   - `same` now additionally requires matching scopeKeyForRoute. This kills the v1.6.0 bug
     where NATIVE_MESSAGE and NATIVE_FEED pooled through PAID_CONTENT.
   - For conversion claims the evidence identity is the TREATMENT key plus sent_to > 0.
     Asset and variant identity are not used at all.
   - For non-conversion placements asset/variant identity is retained, because the audience
     genuinely saw the file before acting.
   - REMOVED from the live path: visualTerm(asset) and variant.technical_score.
   - Shrinkage, EVIDENCE_CAP, fatigue, rotation, recency, quality/scheduling split: unchanged.
   - New return fields: evidence_object, treatment_key, scope_key, conversion_claim,
     denominator_observable, favorable, estimate. evidence adds TREATMENT_HISTORY.

11. CONFLICTS FOUND WITH THE CONTRACT
   a) Item 8 asked for a gate covering "too dark / too blurry". v1.6.0 has NO established
      numeric floor for exposure or sharpness at prescription time, and item 8 also forbids
      inventing thresholds. The gate therefore reuses only rules v1.6.0 already enforced:
      authorization, availability, and a verified privacy-safe derivative. Orientation is left
      where v1.6.0 put it (BEST VERSION display), because promoting it to a prescription gate
      would have been a new rule. Darkness/blur gating needs a threshold you choose.
   b) Test 12 as written is a rendering property. It is enforced two ways: a runtime scan in
      ppv-contract-ui-test.mjs and a build-check assertion, both verified to fail when broken.
